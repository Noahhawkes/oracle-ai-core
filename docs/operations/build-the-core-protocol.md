# Build the Core Protocol

## Status

Operational protocol for Noah AI Technologies AI Compliance Core package creation.

## Functional Mandate

Noah AI Technologies converts enterprise entropy into architectural integrity.

The operating principle is:

```text
Do not merely generate.
Structure, verify, and preserve.
```

## Core Definition

The Build the Core protocol transforms scattered client intake into a governed, audit-ready continuity record.

The client is not buying a collection of PDFs.

The client is buying the ability to look at the business and say:

```text
This is who we are.
This is how we operate.
This is why it works.
This is what must not be lost.
```

## Trigger Phrase

```text
Build the Core
```

When this phrase is invoked with client intake material, the system must produce a structured AI Compliance Core package while preserving strict epistemic boundaries.

## Non-Negotiable Constraints

### 1. Strict Epistemic Boundaries

All outputs must be separated into the following categories:

#### Observed Facts

Data points explicitly present in the client intake.

#### Inferred Hypotheses

Logical conclusions drawn from intake data. These must be marked as hypotheses and not presented as verified facts.

#### Unresolved / Gap

Missing policy, conflicting data, undefined risk area, unclear ownership, or unavailable evidence.

#### Zero Invention

If the intake does not contain a company policy, do not fabricate one as if it exists.

Instead, create a clearly marked placeholder or recommendation.

Example:

```text
Recommendation: Establish a written policy prohibiting employees from entering customer financial data into public AI tools.
```

Do not write:

```text
Company policy prohibits employees from entering customer financial data into public AI tools.
```

unless the intake explicitly supports that statement.

## Build Sequence

### Step 1: Intake Everything

Collect scattered client material without requiring the client to clean it first.

Examples:

- Policies
- Emails
- Screenshots
- SOPs
- Voice notes
- Meeting transcripts
- Software workflows
- Employee questions
- AI usage examples
- Leadership concerns
- Existing documents

### Step 2: Sort the Material

Classify intake into buckets:

- Governance
- Compliance
- AI usage
- Workflows
- People dependencies
- Risks
- Training
- Decision history
- Business playbook

### Step 3: Build the Core

Convert the sorted material into the AI Compliance Core package.

The model must clearly separate observed facts from assumptions and unresolved gaps.

### Step 4: Verify with Client

Ask the client:

```text
Is this how your company actually works?
```

This prevents invented consulting output and preserves witness-grade accuracy.

### Step 5: Seal the Package

Deliver the AI Compliance Core as the official continuity record.

Delivery channels may include:

- Google Drive client folder
- PDF package
- Word documents
- Training deck
- Protected hard drive
- Versioned GitHub template layer

### Step 6: Review Quarterly

Update the package as tools, people, workflows, laws, risks, and business priorities change.
